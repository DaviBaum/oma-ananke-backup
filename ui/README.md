# OMA + ANANKE local workbench

A standalone React, TypeScript, and Three.js interface for the local engine. It reads actual project snapshots, immutable IFC mesh artifacts, checks, candidates, and durable events. It does not generate demonstration models or simulated progress.

From the repository root:

```powershell
npm --prefix ui ci
npm --prefix ui run build
.venv\Scripts\python.exe -m oma.cli serve --port 8765
```

Open `http://127.0.0.1:8765/`. For frontend development, keep the engine running and execute `npm --prefix ui run dev`; Vite serves `http://127.0.0.1:5173/` and proxies `/api` to port 8765. The frontend does not need a cloud account or external asset service. Run `npm --prefix ui test` for the contract, engineering-input, evidence-scope, and geometry tests. A clean `npm ci` and production build were exercised on Node 20.15.1/npm 10.7.0. Exact package versions and integrity hashes are in `package-lock.json`; `dependency-register.json` records package license metadata.

The primary workflow is choose or drop local IFC files (or enter existing absolute paths), inspect input audits and meshes, start an explicit scoped check or routing mission, inspect alternative candidates and their evidence, accept a qualifying candidate, and export a draft or checked release. File transfers go only to the local engine; confirmed receipts retain original byte counts and SHA-256 hashes, and successful receipts are reused after an uncertain retry. Transfers can be cancelled before the import is queued. The server enforces mutation and release predicates. A completed operation is not a global engineering certificate.

The run dialog offers a single route, simultaneous independent route demands, or a shared physical network. The demand table retains up to 16 demands with up to 16 independently editable, explicit scenario options each. It validates all options before submission, identifies the exact incomplete demand/option, and exposes joint-candidate/path limits without treating a bounded search as a global proof. The backend enforces preserved services, loads, clearance, slope, assurance and objective policy, then checks all cross-route geometry. Selected candidates show their actual route membership for inspection and existing materialized-geometry comparison.

Shared-network mode accepts complete graph JSON and offers an explicitly generated, editable geometric example. Each physical segment, elbow and tee is declared once; demand paths reference those components. Its diagram highlights demand membership and distinguishes shared components, while the native IFC viewport renders each materialized component once with its own semantic selection ID. Alternatives preserve fixed terminals and requirements. A new shared mission requires an imported baseline with no existing engineered mission. An accepted single-network state instead offers **Revise this network**: every accepted service requirement is visible and read-only, while replacement graph alternatives remain editable. The editor is bound to the exact accepted head and stops submission if that head changes. Revision lineage shows the union of old and new component IDs and the pinned previous graph; historical replay loads the actual earlier native IFC meshes. Split comparison explicitly identifies when the previous network is not loaded. The engine independently validates the fixed contract and fresh native checks before acceptance or checked export.

The interface supplies no flow, pressure or service assumptions automatically. Service evidence includes aggregate source flow, outward-rounded pressure intervals, per-port flows and velocities, supplied physical assumptions and exact underlying records. This display never computes a new engineering verdict or establishes an operating point.

Historical checker verdicts remain visible beside their current applicability and executable fingerprint. Acceptance and checked export require an explicit `CURRENT` applicability plus a passing verdict; absent applicability fails closed. Recheck submits the candidate's original immutable mission as a durable controllable run with a stable retry identity. A stream reconnection also refreshes the snapshot so changed checker applicability is not left behind after a server update. Public binary redistribution remains a separate, incomplete gate documented in `evidence/dependencies/native-review/README.md`.

Candidate **Evidence** opens conditional support, the recorded engineering verdict, the independent assurance derivation, and explicit fresh-physical-check status separately. Declared scenarios, every trust/model condition, excluded foundations, context differences, dispositions, cores, and external cuts remain inspectable. This query does not rehash external artifact bytes. **Dependencies**, also available for project revisions, exposes actual changed inputs, affected outputs, semantic changes, reused/recomputed artifacts, cold comparison, and input/output dependencies. Queries are cancellable, retryable, and reject responses bound to another candidate or immutable root; they never upgrade physical status.

Known validation advisories are displayed on candidates, checked export, and assurance cases. An advisory blocks acceptance and checked export regardless of a historical passing verdict. Its affected routes, exact reason, source reference, and regeneration/fresh-check requirements remain inspectable. Stopping an evidence query aborts the client wait; its server-side derivation may still complete. The navigation benchmark is available on the current model view, while candidate preview reserves its controls for the geometry comparison.

## Implemented interaction

- One shared world-coordinate origin preserves registration between files. Geometry must explicitly declare meters and world coordinates. Invalid mesh buffers stop rendering.
- Three.js meshes are batched by source discipline and candidate membership. A single-pixel GPU identity pass retains semantic entity selection without scanning tens of millions of triangles on the CPU. Multiple route fitting meshes retain one selectable route identity.
- Source visibility, IFC-type service filter, storey/system filtering, search, selection, isolate/hide, properties, and complete JSON records.
- Perspective, plan, section, horizontal clipping, an editable six-plane section box in world meters, x-ray, fit, focus, zoom, actual collision witness points, and candidate comparison. The envelope display is explicitly a parameterized straight-section guide, not a fitting-clearance certificate.
- Explicit routing inputs include service type, terminals or source/sink IFC port GUIDs, diameter, insulation, bend radius, minimum straight, clearance, and an allowed box. Additional engineering assumptions are entered as JSON. Missing dimensions remain missing; no loads or pressures are invented.
- SSE live events with durable cursor polling fallback. Project switches, out-of-order snapshots, duplicate events, obsolete geometry responses, and immutable root mismatches are guarded.
- Revision and candidate replay use dedicated snapshot and geometry queries. Historical views disable new runs and exports. Evidence is restricted to the selected immutable state or explicitly inspected candidate. Accept and revert use the current live revision plus stable retry idempotency keys.
- Every verdict exposes declared scope, reasons, participants, witnesses, and artifact links. Checks include pass, fail, unknown, blocked, and not-applicable statuses supplied by the engine.
- Hardware and capability diagnostics report observed backend data. API timing, control acknowledgement and observed state timing, and event-stream reconnect timing are accessible through **Diagnostics → Browser timing evidence**.

## Navigation measurement

The viewport's **Navigation benchmark** button fits the visible scene, disables interactive orbit controls, warms up for two seconds, then moves the camera around a fixed full orbit for ten seconds. Each sampled frame renders the real model. Results record immutable root, object/triangle counts, viewport size, pixel ratio, WebGL renderer, delivered frame intervals, CPU submission duration, and the mean 30 FPS gate. CPU submission duration does not include asynchronous GPU completion. When supported, `EXT_disjoint_timer_query_webgl2` samples GPU render duration from the first measured frame, then every ten frames; disjoint queries are rejected and unavailable timing is explicit. A separate 100 ms timer records observed scheduling intervals and document focus/visibility, without replacing RAF measurements or assigning a cause. **Measure without GPU queries** runs the same orbit with GPU instrumentation explicitly disabled. Hidden tabs, changed scenes/settings, and explicit cancellation invalidate a run. A downloadable JSON record is retained in browser local storage.

Measurements describe the specific loaded scene and machine. They do not establish performance for an untested federation. See `qa/` for recorded browser observations and measurements.

## Current limits

The viewport incrementally reads immutable NDJSON mesh streams into typed arrays and prepares complete geometry in cancellable batches that yield to the browser. It commits only the completed scene for the matching project and immutable state. The complete mesh set remains in memory. The legacy JSON endpoint is used only for known small snapshots. Spatial LOD and view-dependent mesh streaming are not implemented. Candidate comparison hides/shows added route and network-component geometry and does not reconstruct an arbitrary removed baseline element. Explicit revision branching, element-lock editing, bounded automatic acceptance, and imported-system tracing require further backend-supported UI flows. Clearance guides cover explicitly parameterized straight sections; full fitting/access envelopes and spatial search-frontier playback are not implemented. The interface is designed for a desktop engineering workstation; very narrow screens hide the inspector.

The scope and completeness of physical verification, IFC round-trip preservation, graph optimization, or engineering-service capability are defined by backend evidence, not by frontend rendering.

## Explicit native host openings

Select an imported wall or slab, then **Prepare opening in this host**. The isolated native inspection reports eligibility and the exact host-local frame. Enter the permitted volume, proposed cut, through-axis and explicit geometric permission, followed by the route scenario. Changing the project head invalidates the form. Scope remains local geometric coordination; this declaration does not provide structural or fire approval. Accepted/candidate views show the actual cut host from the materialized IFC while preserving imported object facts. Replay History to see its original native support. Actual Office display and form evidence: [qa/opening-README.md](qa/opening-README.md).
