# Compact exact top-K finite shared-tree certificate

The existing version1 full-assignment certificate remains unchanged. The separately implemented recurrence certificate checks the first K nominal trees and exact total tree count without storing every complete tree. The complete original source algorithms and native physical authority remain outside this component.

Original source: `math1/math1/the 5 things that combine ceiling router with ananke.docx`, SHA256 `72379f535f744b15ccbdcbbb6f68904f6c1177ace27a8fcc028229039b8bd129`. ALG-RTR17 P5526–5527 explicitly allows finite exact DP and acknowledges exponential terminal complexity. The proposed component supplies discrete topology/ranking, not all those physical obligations.

## State and sufficiency

A state is `(root tee ID, exact sink mask, exact used-tee mask)`. A state label is a complete internal connector-ID set plus its exact nominal `a+b*pi` cost, excluding the entering connector. Each state represents rooted binary trees satisfying all current catalogue cap/section/node rules. Its labelled root outlets determine the left/right child states and connectors uniquely. Leaf states have one sink, no tee, zero internal connectors and zero cost.

The exact tee mask is necessary. For example, a five-sink tree may require rootA→B for three sinks and rootA→C for two sinks. A cheap three-sink subtree rooted atB can itself consumeC, while a more expensive one consumesD instead. Keeping only the cheapest label for `(B,three-sink mask)` would discard the only subtree compatible with the outsideC branch. Distinguishing tee masks prevents this error. Fixed root IDs, all terminal IDs and current catalogue roots also remain necessary.

For a fixed state, replacing an internal subtree by another label of that state leaves all discrete outside compatibility unchanged: the same root input cap is exposed; the same sink and tee identities are consumed; outside selected nodes are disjoint from those inside. Connector identity uniqueness then prevents overlap between inside and outside connectors. This statement is about the supplied discrete catalogue. Geometry interference, operating laws and other native service predicates are not included in this equivalence.

Order labels by exact nominal cost, then sorted connector IDs. Adding the same outside component cost preserves cost order. At an exact cost tie, adding the same disjoint outside connector set preserves the lexicographic order of the sorted fixed-cardinality internal connector sets: the first differing element is the smallest element in their symmetric difference, which an identical disjoint outside set cannot change. All labels of a state have exactly2k−2 internal connectors. Rational-plus-pi cost equality holds only when both rational coefficient differences vanish.

Therefore a label ranked after K within a state cannot occur in the first K complete trees: hold its outside context fixed and replace it by the state's K earlier labels. These are K distinct, compatible complete trees preceding it in the global total order. The same argument applies to either child of a join. It is sufficient to join only the first K labels of each compatible child state, then retain the first K labels of the parent. No physical feasibility property is used or inferred.

## Complete recurrence and independent verification

The producer can build reachable states bottom-up from existing subtree joins. Each recurrence alternative fixes the root's two connector IDs, left/right child root or leaf, and disjoint exact child masks. The parent tee/root is added once. Different alternatives have unique immediate-root decompositions, so no complete tree is double-counted. Alongside top-K labels, a nonnegative exact integer `tree_count` can be computed: sum the product of both child counts over every recurrence alternative. Counts permit a precise catalogue universe size without enumerating all trees.

The checker should use a distinct enumeration: enumerate the bounded potential state keys `(root,leafmask,teemask)` satisfying `|teemask|=|leafmask|−1` and `root∈teemask`, in increasing leaf count. For each key enumerate every partition of its leaf and non-root tee masks, every compatible child root/leaf and both actual outgoing connector options. Recompute reachability, full integer count, exact component costs and the top-K merge from independently checked child records. Absent states must independently have zero count; omitted feasible states, omitted transitions and dropped root entrances must fail. The checker must not call the producer's state discovery/join/heap implementation.

For each recurrence alternative, checking all pairs of child labels is a simple first implementation, bounded by K². More efficient heap/frontier pair certificates can be a later optimization. Source aggregation adds every available source-to-root connector to each full-sink, valid-tee-mask state, independently sums complete counts and checks the final K labels. Each final connector word gets the existing independent complete incidence/path reconstruction.

Proposed separate schema: `oma.shared-tree-topk-certificate/1`, binding raw input root, normalized catalogue root, K, exact theorem/scope header, complete positive-count state records, per-state integer counts and checked top-K connector/cost labels, full source recurrence count, final ranked assignment roots and certificate digest. State/arc decomposition witnesses may be explicit for inspectability, but their denominator must be reconstructed rather than trusted. Version1 certificates and APIs remain valid and unchanged.

The planned API would be `compile_shared_tree_topk_catalogue(problem, *, k=8, budgets..., checkpoint)` and its independent verifier. First supported K should be deliberately small, e.g1–32. Strict input/state/transition/label/count-bit/rational/work/byte budgets and final no-callback original-input/proof guards remain mandatory. Any unclosed state/transition/count/rank returns UNKNOWN without partial optimality authority.

## Complexity and smallest useful consumer

For T=n−1 distinct tees in a fully connected n-sink catalogue, the potential nonleaf state count is `T*sum(C(T−1,k−2)*C(n,k), k=2..n)`. At n=4 this is45 states, compared with720 complete single-option trees. At n=8 it is21,021 states, compared with87,178,291,200 trees. The actual authored four-sink catalogue already checked by version1 has18,048 trees but at most45 such state keys. With K=8 its stored positive-state labels would be bounded by360, plus the complete recurrence/count evidence. These are combinatorial bounds, not runtime guarantees: partition enumeration and K² products remain exponential/budgeted and may still be too large.

The smallest actual consumer is the existing finite generation job's nominal proposal prefix. The new checker can return exactly the same first K assignment/geometry proposals as the existing fully enumerated version1 proof for small catalogues, while using a different certificate kind and fewer stored labels. Full current macro provenance checks, final current roots, native materialization, geometry, operating and service checks remain mandatory. A native-rejected nominal prefix does not prove the remaining physical universe empty or optimal.

Initial independent tests should compare the entire new top-K output and exact full count against version1's independently checked small4–8 catalogues, and use the separate incoming-parent-function oracle on complete4-sink and actual18,048-tree examples. Add the missing-tee-mask counterexample, exact tie/context union cases, parallel connector counts, missing state/split/root entrance, count overflow, false predecessor/cost/truncation, and byte/work/callback attacks. `assessment.json` records small exact tie-union checks and the independently calculated state/assignment counts. Implementation remains subject to a separate approval and scope.


## Implemented API and independent proof replay

The module is `oma.optimization.shared_tree_topk`, with `compile_shared_tree_topk_catalogue(problem, *, k=8, ...)` and `verify_shared_tree_topk_catalogue(problem, certificate, *, k=8, ...)`. The supplied catalogue schema and exact parser are the unchanged `shared_tree_synthesis.py` dependency SHA256 `9a9f6c76b4691d70d5d9a21a5a371635549992f5de06fbd0f4ffaf745c97c55d`. Existing full-ledger functions/certificates remain unchanged.

Production returns CERTIFIED and independent replay returns PASS only after full closure. Both return `proof_complete`, input/problem/certificate roots, exact existing proposal dictionaries, scope, counted work and counts. `counts.complete_assignments` is a canonical decimal STRING because the exact count can exceed a machine integer; `returned_proposals` is an integer. The proposal shape is identical to version1 (`tee_ids`, `connector_ids`, exact nominal cost, assignment root, source, sinks/demand paths, connections). The separate certificate schema is `oma.shared-tree-topk-certificate/1`; neither verifier accepts the other's schema.

Certificate fields are `schema,input_root,problem_root,k,scope,limitations,state_domain_count,states,total_tree_count,ranked_prefix,certificate_root`. Only positive-count states are stored. Each has `state:[root_tee_id,sink_mask,tee_mask]`, canonical decimal `tree_count`, and its exact ordered labels. A label binds sorted connector IDs, rational-plus-pi cost and a label root tied to its state and normalized problem. Final prefix rows use the same assignment-root formula as version1. Masks use the normalized sorted tee and sink orders. Typed state/header integers reject Python boolean aliases.

The producer discovers states through disjoint child joins, retaining K labels by sorted binary insertion. The independent checker enumerates all potential mask states and their labelled partitions, recomputes each exact recurrence/count/cost, and retains K labels using a separate unsorted worst-element buffer before sorting. It calls no producer state discovery, combination, insertion, full-ledger enumeration or producer pi helper. Checker joins separately reparse the admitted root/edge cost records and combine them with already checked child costs.

To avoid expensive partitions for states that are provably empty, the checker independently computes directed reachability in the subgraph induced by that state's selected tees and sinks. A valid subtree must reach all its selected nodes using only selected nodes, so failure proves that state has zero trees. Passing this necessary test supplies no feasibility authority; all remaining recurrence/partition obligations still run. This enabled sparse eight-sink positive certificates while preserving the original budgeted-UNKNOWN smoke result before the improvement.

## Bounds and controls

Supported K is1?32. Defaults are50,000 potential states,500,000 attempted recurrence transitions,2,000,000 candidate label pairs,256 count bits,16 tees,256 connectors,2,000,000 work units,16MiB per input/certificate,4,096 rational bits and128 Machin terms. Explicit supported ceilings are100,000 states,2,000,000 transitions,10,000,000 label pairs,4,096 count bits,64 tees,4,096 connectors,20,000,000 work and64MiB. These are separate ceilings, not joint completion promises. The full potential state-domain cardinality is checked before allocation. Candidate transitions and label pairs are charged before combination/allocation; unsuccessful scans and source/state membership scans also consume work.

Canonical JSON shape/byte guards precede semantic parsing, captured shapes are checked again, and count strings are digit-bounded before integer conversion. Rational parsing uses the existing strict rational grammar, which rejects exponents before Fraction construction; arithmetic bit guards remain in every cost accumulation/comparison. Count products have bounded operands and are bit-checked before use. All incomplete resource outcomes return UNKNOWN with no proposals or partial proof authority. Final callbacks precede current original input/proof hashing with no later callbacks. Caller exceptions retain their exact identity. These are cooperative in-memory bounds, not an atomic filesystem or hard process deadline claim.
