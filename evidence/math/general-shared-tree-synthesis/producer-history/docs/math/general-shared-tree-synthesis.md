# Bounded finite catalogue synthesis for four through eight sinks

This private extension retains the existing `oma.shared-tree-catalogue/1`, certificate schema and public `compile_shared_tree_catalogue` / `verify_shared_tree_catalogue` APIs. Existing two/three-sink producer branches, certificates, returned results, work accounting and callbacks are preserved. Four through eight sinks use a new finite dynamic program. Native catalogue production, geometry/service checking and application integration are separate work.

## New producer and independent completeness proof

For n>3, the producer constructs complete tee-rooted subtrees by increasing leaf count. A state stores its root tee, sink bit set, used tee bit set, and complete selected connector IDs; it excludes the entering connector. For a root's labelled `b` and `branch` outlets, each outgoing connector either reaches a singleton sink or the root of an already constructed smaller subtree. A join is admitted only when the two sink sets and two tee sets are disjoint and neither child contains the new root. The new root and its two connectors are added once. At n leaves, every source-to-root connector produces a complete assignment.

Induction on leaf count proves soundness: a singleton sink is a leaf; disjoint rooted children joined to a fresh root form a tree with complete labelled outlets. Conversely, every admitted finite tree has a unique root and labelled pair of children. Each child has fewer leaves and appears in the prior tables; its entering connector is in the supplied outgoing catalogue, so the unique pair is joined. Parallel connector records are distinct choices. No subtree can appear twice with identical connector IDs because its labelled root connectors and child decompositions are unique. At the source every complete catalogue tree is therefore included exactly once.

The verifier does not invoke this DP, its subtree table, or producer cost routines. It independently starts at the source output and follows every outgoing connector for the first remaining open slot. An unused tee appends its two named outlets; an unused sink closes one slot. Reusing a tee or sink is forbidden. Every successful completion has all sinks and exactly n−1 tees. Each step adds a new node, so cycles are absent; conversely every valid tree has its actual connector available at each open slot and cannot trigger a reuse rejection. Thus the verifier reconstructs the same full finite universe by a materially different traversal.

For the new domain, the verifier separately accumulates each selected tee/connector's normalized rational cost coefficients exactly once. Shared trunks are not charged once per demand path. It independently reconstructs all rows and compares the entire sorted ledger, costs and assignment roots, then checks the exact nominal ranked prefix with the existing independently computed rational Machin bounds for pi. No result prefix is authorized before full closure, even when `max_results=1`.

## Complexity, resource contract and failure meaning

With T available tees and one connector per admissible cap pair, the fully connected catalogue has `Catalan(n−1) * P(T,n−1) * n!` complete trees. Parallel connector choices multiply that count per tree. Four sinks/three tees already give720 assignments; eight sinks/seven tees give87,178,291,200. These are complexity warnings, not promised supported default workloads. Sparse catalogues with four through eight sinks can close usefully.

The new optional keyword `max_partial_trees=20000`, supported1–200000, bounds attempted subtree joins in the producer and attempted open-slot visits/transitions in the verifier. The counters are charged before overlap tests, recursive successor/result allocation, or stored joined states. Consequently stored subtrees cannot exceed the bound. Existing work bounds also charge unsuccessful connector/size scans; an empty or incompatible join cannot evade the work budget. The old two/three-sink branches preserve their original behavior and do not use this additional domain-specific search budget.

The remaining defaults and hard limits remain unchanged:16 tee instances,256 connectors,100000 complete assignments,32 returned proposals,2000000 work units,16MiB per input/certificate,4096-bit rational arithmetic and128 Machin terms. Explicit maxima are not joint tractability guarantees. More than eight sinks is `UNKNOWN/SINK_DOMAIN`; malformed input is invalid. Exhausted work, partial-tree, assignment, rational, byte or pi budgets yield `UNKNOWN`, an empty proposal list and `proof_complete:false`. No partial ledger or partly ranked prefix is published as a proof.

All caller input/certificate JSON is shape-checked before bounded copying and rechecked afterward; exact rational parsing rejects scientific notation before Fraction allocation. Final caller callbacks precede current original input/proof hashing with no later callbacks. Original callback exception objects propagate. Returned certificates bind the entire input and output-limit semantics, not native truth of opaque macro roots.

## Independent validation and nonclaims

The oracle assigns exactly one incoming connector to every selected non-source node, then independently checks source reachability, unique output slots and complete degrees. It uses neither subtree joins nor open-slot traversal to enumerate candidates. The fully connected four-sink case must give720 complete assignments; sparse four–eight-sink catalogues, parallel choices, disconnected/cyclic distractions, unused tees, and common-trunk cost examples provide additional oracles. Resealed missing/duplicate/cost/rank/context/cap attacks, producer-disabled verification, exact resource boundaries and callback mutations challenge proof integrity. All85 original tests and byte-for-byte old result/callback comparisons remain in the private validation denominator.

This is exact nominal ranking only within the complete supplied finite catalogue. Opaque geometry/fabrication/loss identities require a separate current provenance checker and native physical/service checks. The existing native adapter is still limited to its admitted sink domain. Empty catalogue results do not prove physical infeasibility; nominal rankings do not provide native objective bounds; no unrestricted topology, connector, sizing, homotopy or continuous optimum is claimed.
