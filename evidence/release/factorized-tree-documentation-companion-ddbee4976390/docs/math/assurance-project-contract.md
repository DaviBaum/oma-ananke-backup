## Executable assurance contract

`oma.assurance.solve_assurance` takes a finite positive Horn theory with typed claims, nonempty-premise inferences, evidence/trust/assumption foundations, an explicitly enumerated exact-context family, authenticated foundation IDs and an assessment time. It constructs grounded support witnesses and the complete antichain of inclusion-minimal foundation sets for each claim. Target cores are the conjunction across every listed target. Alternative derivations remain available after another foundation is revoked. A foundation-free cycle yields no claim.

`verify_assurance` independently replays every witness in dependency order. It checks every applicable direct foundation, antichain minimality and closure under every premise combination of every admitted rule. Grounded witnesses establish one inclusion in the least closure; complete closure establishes the reverse inclusion. It does not rerun the producer's refinement algorithm. Work exhaustion is UNKNOWN, with no complete-core assertion.

Applicability is deliberately conservative: every member of the requested family must equal the foundation's **entire** binding dictionary. This is not a general partial-binding or symbolic universal-applicability engine. Validity intervals are `[from, until)`. Observation-time evidence can remain usable after a later calibration expiry if its observation was in the valid interval; an observation after the assessment time cannot yet support that assessment. Revoked/unauthenticated foundations do not support a claim.

`evidence_cuts` enumerates minimal hitting sets of the complete core family, excluding TCB/model assumptions from the external-evidence universe. These are ways to disable existing proofs, not sufficient repair plans. An evidence-free trusted core has no external-evidence cut. Minimum-cardinality cores, uniqueness and global repair optimization are not inferred from inclusion minimality.

## Actual application integration

`oma.project_assurance.build_report_assurance` reloads the exact persisted candidate and independent report. Each successful checker disposition has a narrow claim, scope and evidence root. The root conjunction requires all dispositions, recorded PASS, no unresolved known validation advisory and all stated model/trust conditions. Report root, mission, rules, scenario, catalog, numerical policy, source manifest and executable version are bound. Authenticity of stored bytes does not establish the truth of model assumptions or the absence of shared-kernel defects.

`Store.record_verification` persists the assurance case and its independent closure-check result in the same verification event graph as the original checker report. `GET /api/projects/{project}/candidates/{candidate}/assurance` assesses that evidence against current software. It does **not** rerun native geometry or hash external files; those are explicitly NOT_RUN/NOT_REHASHED in the response. Conditional support is not a new physical PASS, professional approval, whole-building release or optimality claim. An advisory can invalidate current support while the immutable original report retains its historical disposition.

`oma.project_dependencies.derive_transition` constructs guarded dependencies from real persisted project state. It recomputes source inventory, declared explicit connectivity, demand membership and complete physical/service input fingerprints. All source products and all routes remain inputs of route-clearance derivations. Inferred connections are not promoted to explicit connections. Full entity content digests preserve changes to arbitrary properties while avoiding repeated copying of large IFC property dictionaries. Every authoritative extension field is included in the complete-state input artifact.

Every publication of a typed engineering revision compares incremental outputs and applicability keys with a fresh cold dependency rebuild before committing its event. The event references the complete transition artifact. It separates conservative affected closure, actual recomputation, semantic output changes and reused results. Native CAD and simulation PASS are **not reused across different state roots** by this module: full numerical recomputation remains the independent checker's responsibility. `GET /api/projects/{project}/dependencies` exposes the exact graph and artifacts for a revision or candidate.

## Evidence and limits

- `tests/test_assurance.py`: alternate proofs, ungrounded cycles, forged closure, core/cut semantics, universal exact-context checks, chronology/expiry and 80 independently enumerated small Horn theories.
- `tests/test_project_dependencies.py`: real typed-state projections, distant obstacle invalidation, nonlocal flow changes, newly introduced fields, reserved-looking identities, persisted cases/revision events and portable backup roots.
- `evidence/benchmarks/dependencies/wbdg-office-simultaneous.json`: actual two-route candidate transition, source inventory reuse and cold equivalence. This evidence was captured before the subsequently identified IFC port-semantic amendment; it is a metadata/dependency result, not a new IFC conformance certificate.
- `evidence/benchmarks/dependencies/sixty5-full-frozen-compact.json`: all 188,312 source entities and seven disciplines; unchanged-state reuse equals cold reconstruction in 7.70 seconds on the recorded immutable build. The earlier live-source performance probe was stopped at 381 seconds and is retained with no completed equivalence claim.
- `evidence/release/full-suite-assurance-checkpoint.xml`: 205 tests passed on the recorded checkpoint. Later standards review found IFC-PORT-001 despite those tests; passing tests are not treated as proof of complete engineering semantics.

Original ASS3's arbitrary omitted-claim countermodel argument needs a non-entailment qualification. ASS14's SCC argument needs a defined intra-SCC closure contract; arbitrary deterministic cyclic equations need not have a unique fixed point. The existing dependency engine handles explicitly finite monotone product-chain cycles and verifies their tables. The project derivations here are acyclic. Neither this contract nor its tests assert complete whole-building obligations, arbitrary evidence authenticity, complete dependency discovery or unlimited graph scalability.
