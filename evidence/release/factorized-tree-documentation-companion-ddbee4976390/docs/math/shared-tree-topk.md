# Compact exact top-K shared-tree synthesis

The f73 checkpoint supplies a separately checked compact recurrence for the first K exact nominal trees and the full assignment count in a supplied 2-8-sink catalogue. Existing FULL_LEDGER APIs, default selection and certificate remain unchanged. Compact proof does not establish geometric feasibility, native cost bounds, a complete connector language, or unrestricted topology/placement optimality.

## Source and proof domain

Original read-only `math1/math1/the 5 things that combine ceiling router with ananke.docx`, SHA256 `72379f535f744b15ccbdcbbb6f68904f6c1177ace27a8fcc028229039b8bd129`, ALG-RTR17 OOXML P5526-5527 permits finite exact DP and retains exponential terminal complexity. ALG-RTR18 P5528-5529 requires independent terminal/junction/loop/class/embedding/context checks. Only the finite discrete component is implemented here; every original full-algorithm flag remains false.

A state fixes its root tee ID, exact sink mask and exact used-tee mask. It exposes that root's input cap and contains complete internal connector-ID words. The exact tee mask prevents a cheap subtree that consumes a needed outside tee from replacing a more expensive compatible one. Labelled b/branch outlets and physical tee identities cannot be interchanged. Each selected tee/connector contributes its cost once, including shared trunks.

Within one state, replacing an internal word by an earlier nominal word preserves the exposed cap and all consumed sink/tee identities. Outside nodes are disjoint. None of the replacement connector IDs can occur outside without consuming the same source slot twice. Adding the same outside cost preserves order; at exact cost ties, sorted disjoint connector-set union preserves the first symmetric difference. Therefore any label after K has K distinct preceding complete substitutions and cannot appear in the global first K. This is discrete compatibility, not native clearance or hydraulic equivalence.

Same directed cap-pair connectors can be grouped with full multiplicity retained in counts. Only the first K edge choices are needed for labels by the same substitution argument. Complete attachment counts are multiplicity times child count; parent counts sum products over all disjoint labelled child-mask partitions. Auxiliary attachment state fixes parent tee, labelled outlet and exact consumed masks. Grouping different physical geometries gives no permission to reuse a native verdict.

The producer discovers states bottom-up. The checker independently visits the bounded potential state keys, reconstructs every legal mask partition/child/root connection, independently computes costs and top-K labels, and requires omitted states to have zero count. Complete source aggregation and realizing connector-word incidence are checked. The checker does not call the producer's discovery/merge routines. Grouped implementation changes operation counts while retaining byte-identical certificates for completed legacy compact queries.

## API, schema and bounds

`oma.optimization.shared_tree_topk.compile_shared_tree_topk_catalogue(problem, *, k=8, ...)` returns CERTIFIED; `verify_shared_tree_topk_catalogue(problem, certificate, *, k=8, ...)` returns PASS only after full proof closure. K is 1-32. The catalogue schema and returned proposal dictionaries match full-ledger consumption. The distinct certificate schema is `oma.shared-tree-topk-certificate/1`. `counts.complete_assignments` is a canonical decimal string; `returned_proposals` is an integer. Ranking uses exact rational-plus-pi nominal costs followed by deterministic sorted connector-ID ties. Unresolved comparisons, count/state/transition/label/bit/byte/work exhaustion return UNKNOWN with no partial prefix or count authority.

The application chooses this method only through `proof_method: COMPACT_TOP_K`. Defaults remain 2M cumulative work, 500k compact transitions, 2M label pairs and 16MiB compact proof/output. FULL_LEDGER's maximum remains 10M. Explicit COMPACT_TOP_K can use 48M cumulative work, at most 2M transitions, 10M label pairs and 32MiB proof/output. Each nested compact producer/checker is still capped at 20M and the independent macro checker at 10M, all using the remaining cumulative grant. Authored input 2MiB/40k items and generated-macro 400k items remain separate bounds. Final copying, hashing and publication checks consume the same grant. Exact supported limits do not imply every catalogue/K completes.

The measured eight-sink K=2 job needs the explicit 48M/32MiB policy and completes at 44,065,040 total work. Its old 40M exhaustion and earlier 16MiB proof failure are retained. The unchanged four-sink full-ledger 10M job completes at 9,706,419. A generated mission is still only a proposal: source/CAD/component/cap/native pressure/service checks, revision acceptance and fresh export remain separate operations. Late callback mutations of raw policy, query, macro packet or retained producer/checker proof cannot change an authoritative published packet.
