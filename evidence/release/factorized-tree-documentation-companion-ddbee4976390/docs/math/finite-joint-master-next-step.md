# Next bounded integration: finite joint proposal master

This records the read-only design assessment used to select the next component. The approved **fresh native pair counterexample gate guided by earlier failed pairs** has subsequently been implemented; its current contract is in [fresh-joint-counterexamples.md](fresh-joint-counterexamples.md). The finite multi-choice master and general resource extensions discussed below remain later work. Earlier results supply hints only. This first establishes applicable conflict evidence before expensive complete source scans; it does not establish reusable cuts across materializations. The existing native joint checker remains the acceptance authority. No new corridor capacity or sharing rule should be invented from geometric proximity.

## Current code and supplied source

`optimization/master.py` already supports exact rational per-column costs, nonnegative additive resource consumption, one selection per net, and literal pair/clique/general forbidden-joint constraints. `price_columns` evaluates every supplied column; `generate_columns` proposes restricted LP solutions and repairs their dual against that explicit finite universe. `optimization/checker.py` independently checks all finite dual column inequalities and can exhaustively check small integer masters. General activation variables, branch automata and infinite route families are not represented.

`routing/joint.py` currently freezes actual generated choices, traverses their Cartesian product in enumeration order and physically materializes/checks each visited full assignment. Its subsequent co-design master has just one column per already chosen route. It therefore verifies costs after assignment checking but does not yet exploit a multi-choice conflict/resource master to decide which combination to try next. The source-bound nominal graph/pricing proofs now feed each demand's proposal list; they do not yet serve a shared master pricing oracle.

Supplied integration SHA `72379f535f744b15ccbdcbbb6f68904f6c1177ace27a8fcc028229039b8bd129` supports the following exact obligations. DEF-RTR62–63 at paragraphs 4689–4701 binds geometry, physical coordinates, costs, resource usage, proof modality and versions to a column. DEF-RTR67–72 at paragraphs 4729–4774 defines represented versus restricted universes, master rows, dual signs and complete pricing. It expressly limits shortest-path pricing to choices reducible to additive edge costs. DEF-RTR73–75 at paragraphs 4775–4788 requires a lower bound over the entire pricing domain and retains ambiguous intervals as UNKNOWN. ALG-RTR23–28 and ALG-RTR31–33 at paragraphs 5538–5559 specify the checked column-generation/branch/Farkas boundary. DEF-RTR81 at paragraphs 4875–4880 requires additive sharing semantics for resource cuts and explicitly excludes an unrepresented shared-trunk reduction. The proposed failure gate is an implementation refinement of checked conflict discovery, not completion of this full algorithm family.

The existing general hyperedge correction remains essential: a jointly forbidden set H means `sum(x_i for i in H) <= |H|−1`; it means `<=1` only when every pair is actually incompatible.

## Recommended first component and actual consumer

For a fixed current candidate A, its physical feasibility entails the conjunction of all required cross-route pair predicates. A fresh conclusive failure of one required predicate therefore refutes A. This argument needs neither a complete remaining geometry denominator nor proof that A is the same geometry as an earlier candidate. It does require proving that the two current bodies and the checked hard rule really belong to A.

The producer can learn an untrusted hint `(demand, option, component)` for each participant from an earlier current-check failure. Assignment ordinals change route IDs; native GUIDs and composite IFC byte identities also change. A stored option or waypoint label is consequently insufficient to transfer any old physical verdict. The gate resolves a hint to actual parts in the **new** materialization, independently reloads those parts and freshly executes the current native predicate. Even a forged or incorrectly mapped hint can only choose a different pair to investigate; independently validated current membership and rule applicability remain mandatory.

The consumer is the independent composite checker, after cheap current-state preflight and before the full per-route source scans. The gate must perform or preserve the following checks:

* Bind current candidate, run, immutable request, baseline, full source hashes, edited-file hashes and current checker build. Rehash checked files around the native operation. Validate the current composite mission before publishing an early report; it presently appears after the expensive checks.
* Reconstruct complete current route/component ownership and new-part semantics, authorized alternatives, source bindings and protected original effects. Original STEP string equality alone does not detect appended relationships targeting old objects; preserve `added_relationship_effects` and the existing inverse-effect protections. Missing or ambiguous component mappings fall through to full checking.
* Independently audit the common frame from the current immutable sources, then transport freshly loaded native bodies with the current verified transforms. A stored materialization matrix alone is not authority. Require both complete native bodies to support a negative result; outer enclosure overlap provides no such proof.
* Recompute the pair rule from the current two authorized scenarios. In the independent-route joint model this uses `max(clearance_first, clearance_second)` and the current numerical tolerance. Shared-network authorized contact/fitting interfaces require a different contract and are excluded from this initial gate.
* Accept only a fresh `check_pair` FAIL for positive common solid volume or a clearance violation beyond its stated numerical budget. PASS, BLOCKED, UNKNOWN, failure to load, changed files, exhausted work or cancellation must not create an incompatibility. Successful absence of a hinted counterexample still requires the complete checker.

Suggested result schema is a rooted `COUNTEREXAMPLE_FOUND` or `NO_COUNTEREXAMPLE_FOUND`, with current candidate/source/export/frame/build roots, current participants, actual rule and numerical assumptions, the newly computed native witness, bounded probe count and timing, and the old hint origin explicitly labeled nonauthoritative. On a counterexample, the report contains one current hard-rule FAIL; all unperformed route/source, self-contact, engineering, permitted-zone and objective obligations remain NOT_RUN. Retain the expected declared component/obligation counts when available, the actual number of tested pairs and `complete_component_coverage: false`; do not invent a checked source denominator. An early rejected candidate must have no computed-objective or acceptance authority. The complete verification path remains unchanged when the gate finds nothing.

The comparison uses the same declared numerical CAD contract as the ordinary checker, not an exact real-solid intersection theorem. Its correctness gain is applicability and fresh execution, not a stronger native kernel.

Bound the number of hinted pairs and check cancellation/deadlines between native operations and before publication. An OCCT operation itself is not cooperatively interruptible, so a strict local wall-clock limit requires a supervised native subprocess; otherwise state that the enclosing independent checker timeout supplies that limit. A final checkpoint prevents a result from being published after cooperative cancellation, but does not by itself bound time spent inside a native call.

Meaningful validation uses three demands: A and B recur unchanged as logical options while C changes, producing new route IDs/GUIDs and IFC bytes. Their current bodies still clash, and the hint gate freshly detects that pair while avoiding complete source scans. A different realization that separates A and B must fall through and receive a full check. Additional tests cover wrong/stale labels, duplicate or missing component ownership, source/frame/clearance changes, forged previous FAIL, outer-only support, UNKNOWN/near-threshold contact, original inverse-effect mutations, cancellation and source mutation during the probe. Instrument native call counts: demonstrate a new pair computation and zero skipped-source scans on a conclusive counterexample. Final accepted alternatives still receive the full current native checker and export verification.

## Subsequent finite master connection

A literal full-assignment no-good is mathematically sound when its exact current assignment has a conclusive applicable hard-rule failure, but the present Cartesian-product loop visits each tuple once. Such a no-good alone provides little additional speed. The fresh-pair gate gives a useful earlier stop without prematurely claiming a cut valid across different realizations.

A later bounded scheduler can consume the complete frozen menu, declared proposal-priority costs, applicable literal cuts and optional explicitly supplied additive resources through the existing exact master. Checked assignments remain a full outcome ledger; UNKNOWN is never an infeasibility cut. A pair cut that skips materialization entirely needs an additional invariant proving that both realized bodies and their hard rule remain the same across every allowed remaining choice. The current hint gate intentionally does not establish that invariant.

Source-bound nominal graph pricing supplies useful routes to the menu. Scheduling can use a declared rational proposal priority derived from the same user weights and nominal path expression, while native report costs select the actual incumbent. The scheduling optimum is over its explicit priority and finite menu, not the native measured physical objective. An actual master lower bound requires a justified cost bridge and complete pricing domain; neither follows from labeling the nominal path shortest.

## Resource and pricing premises that are still missing

Capacity is not collision. A scalar route resource row requires an explicit definition and authority: resource identity, units, capacity, per-route usage, all sharing/activation semantics, and a proof that usages compose additively. Two pipes occupying the same wide corridor need not be incompatible, and count/area capacity alone does not prove packability. A shared trunk can consume one physical resource while serving several demands; summing independent route demands can then overcount. The current independent-route joint model excludes new shared junctions and does not provide an arbitrary corridor-capacity registry.

An exact count of newly fabricated elbows is one technically simple additive resource for disjoint route components. A hard total-elbow budget must nevertheless be explicitly supplied by a mission; it cannot be inferred or silently introduced. It would yield an immediate subsequent pricing adapter: a nonnegative multiplier adds to the existing per-elbow weight, while the exact native component denominator verifies realized usage. Native objective length remains a separate numerical quantity, so an exact nominal graph price does not automatically certify a lower bound for the native-cost master.

The present dual convention is

`reduced_cost(route) = cost(route) + sum(lambda_j * usage_j(route)) − alpha_net`, with `lambda_j >= 0`.

For nonnegative additive usage, resource tolls preserve nonnegative graph edges. `alpha_net` is subtracted once from the completed route price; it need not become a negative cost on every edge. Thus the current sparse capped-potential proof can be extended for such tolls without introducing negative cycles. The existing solver can already handle a per-elbow toll through a changed `fitting_weight`.

Arbitrary conflict membership is not an additive edge statistic. A row referring to specific complete columns can retain those literal memberships and give a newly named column coefficient zero, but the resulting row is only that specific valid inequality; it does not represent every physical clash involving the new route. Pricing an exact whole-path membership penalty requires additional path-language state or a finite explicit column scan. Charging one conflict penalty per intersected segment would count repeated visits incorrectly. Activation costs charged once likewise require a visited-resource flag or equivalent state.

If a future branch or resource model actually creates negative graph edges, the current Dijkstra/sparse-default theorem is inapplicable. A general full finite potential with all relevant edge inequalities, certified absence of an improving negative cycle, or a correctly bounded path/resource domain is then required. Excluding cycles without a source argument can discard valid physical routing possibilities; allowing negative cycles in an unrestricted walk model can make its value unbounded below.

## Claims to keep open

A complete finite generated menu is not the full represented graph route universe, and that graph is not the continuous routing universe. A restricted master optimum/infeasibility does not transfer to either larger family. Even with all nominal graph prices closed, physical fibers, branch state, nonadditive interactions and actual cost lower enclosures must be included or bounded in the correct direction before claiming a full physical master bound. An LP dual lower bound is not an integer optimum unless the remaining gap/branch proof is closed. A restricted Farkas ray needs Farkas pricing over every omitted valid column; failure to find a replacement route is insufficient.

For the proposed first component, publish only freshly checked current-assignment counterexamples and explicit unperformed obligations. Keep global physical lower bound/gap absent. This improves real simultaneous-route checking while leaving the larger source obligations explicit and reviewable.
