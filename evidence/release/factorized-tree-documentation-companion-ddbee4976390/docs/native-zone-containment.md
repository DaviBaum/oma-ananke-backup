# Native permitted-zone containment and search margins

`routing/native_zone.py` independently reconstructs whole-shape native bounds for every materialized route part. It uses OCCT `BRepBndLib.AddOptimal` with triangulation disabled and shape tolerances enabled, then rounds each returned endpoint outward by one representable float. OCCT documents this routine as providing more precise geometry bounds while retaining the requested shape tolerances. [OCCT 7.8 reference](https://dev.opencascade.org/doc/occt-7.8.0/refman/html/classBRepBndLib.html)

This remains a numerical CAD checking contract. In particular, native surface minimization is not an exact rational enclosure proof. The checker does not use displayed meshes, a producer's polyline or a nominal fabrication certificate as the actual-solid containment oracle. Source obstacle bounds and native collision checking retain their existing implementations.

For each part, the witness records its IFC GUID, earlier broad bounds, freshly computed bounds, kernel tolerance, all six permitted-boundary gaps, minimum gap and required strict gap. The acceptance rule is unchanged: any negative gap fails; a nonnegative gap at or below `1e-6 + kernel_tolerance_m` is UNKNOWN; only a larger gap passes. Missing or duplicate parts, native geometry errors and unavailable valid solids cannot pass. Native bounding failure or an open, void, nonfinite or reversed box remains UNKNOWN. A separate failed part retains precedence over another part's uncertainty. Caller cancellation propagates unchanged before each native operation and before final publication.

The helper revalidates the supplied allowed bounds even if a caller used a validation-bypassing model copy. It requires a positive integer expected-part count. Invalid diagnostic native numbers are represented as null rather than contaminating immutable JSON with NaN or infinity. Physical validity remains false or unresolved in those cases.

The source-bound search separately moves the declared graph's allowed **body** box inward by 100 micrometres. Its original mission bounds are preserved and bound in `search_domain`, together with the narrower graph box and explicit guard. All graph bodies must fit that inner box. This encourages numerically robust proposals; it is not a certified error allowance for arbitrary CAD or an assertion that every physical route can be represented there. Terminals or geometries excluded by this restricted model produce UNKNOWN, and other proposal methods remain available. All emitted candidates still require the original mission's fresh native check.

The initial real Office pricing attempt at `ebe15db2...` supplied a useful counterexample. Its nominal body reached the zone boundary. The previous native `Add` bounds extended both elbows about 30.495 mm farther than the nominal support; independently reconstructed `AddOptimal` bounds differed outward by the 10 micrometre kernel tolerance, consistent with sampled native surfaces, edges and vertices. The original candidate still fails with the tighter bounds because it touches the boundary before that tolerance. Its REJECTED status and failed campaign are preserved. No historical native verdict is upgraded by this change.

Six actual IFC quarter-bend tests cover all three coordinate planes and both signed incoming directions. They reproduce broad-bound inflation beyond a permitted side despite a 5 mm actual margin, and pass with independently rebuilt tighter bounds. Moving the permitted side inward still produces FAIL; a tiny positive uncertain margin remains UNKNOWN. Missing-part and native-error checks, per-part/final cancellation and adversarial malformed bounds are retained in `tests/test_native_zone.py` and `tests/test_native_zone_adversarial.py`.
