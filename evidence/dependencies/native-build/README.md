# Isolated IfcOpenShell build evidence

The isolated Windows source build produced a candidate wheel that passes all eight exact schema smoke cases, all 916 tests from the pinned application baseline, and a complete recheck of an existing real Office exported route. Outputs and test interpreters stay under `.release/native-build`; the application `.venv` and retained original wheels are unchanged. `handoff.json` binds the completed evidence. Runtime promotion and public redistribution remain separate decisions.

The inputs are IfcOpenShell commit `1c5b825d8ef05ab9d14a15dac12e9eae2f5a37c2`, OCCT 7.8.1 with the retained upstream Windows patch, Boost 1.86.0, Eigen 3.3.9 at `0fd6b4f71dd85b2009ee4d1aeb296e2c11fc9d68`, and SWIG 4.2.1 at `b592468f522cf7f4a0812493bfa07cbe60679d7c`. Raw downloads, archive hashes, extracted source-file hashes, notices, compiler identity, generated configurations and command logs are retained. The SWIG Windows executable is a build tool, separately hashed alongside its source revision.

The selected IFC variant enables STEP input, all eight compiled IFC schemas, the Python wrapper and OpenCASCADE geometry. CGAL, SVG fill, IFC XML, HDF5, COLLADA, glTF, PROJ, RocksDB and ZSTD are disabled. `ifc-variant.json`, actual `CMakeCache.txt` and compiler commands are the configuration evidence. No feature omitted from this variant inherits a compatibility claim from the original wheel.

Every command gets a separate `commands/<stage>-<id>/record.json` and full output log. Failed attempts remain beside subsequent attempts. Four compiler jobs are used; process-tree memory and wall time are bounded. Creating `.release/native-build/CANCEL_BUILD` cancels the active build at the next monitor poll. The child compiler environment is isolated from the host. Boost's batch helpers require their exact retained engine directory on the child PATH because this machine disables implicit current-directory executable lookup.

OCCT configuration, compilation and installation passed, followed by Boost compilation. The first IFC compile failed because the upstream manual `OCC_INCLUDE_DIR`/`OCC_LIBRARY_DIR` fallback did not propagate the header path to its directly linked `TKernel`. The subsequent configuration uses the same SDK's installed `OpenCASCADEConfig.cmake` imported targets. No IFC source or geometry rule changed to address that build configuration issue.

The next IFC attempt compiled the geometry libraries and all eight schema mappings, then exposed an upstream CGAL-disabled wrapper defect: the generic `OpaqueCoordinate<3>` and `<4>` SWIG template declarations were inside the optional CGAL guard. The retained minimal patch moves those two declarations above that guard. It changes no geometry kernel code. The resulting wrapper compile, link and installation passed. `ifc-opaque-coordinate-patch.json` and `patches/ifc-opaque-coordinates-nocgal.patch` record the exact change; both failed compile attempts remain in the command ledger.

`source-revalidation.json` checks every retained archive member and the declared OCCT patch. Its IFC scan happened before the wrapper patch; `source-revalidation-ifc.json` separately rehashes all 3,510 IFC archive members after the patch and permits only that exact declared modification. Generated compiler/wrapper outputs have separate hashes. These records do not assert that all sources were checked in one simultaneous snapshot.
