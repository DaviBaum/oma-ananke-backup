# IFC evidence

`summary.json` is the compact acquisition and import register. It covers all **50 IFC files across 22 projects**, including all **33 IFC files in the six required projects**. The hospital IFC2X3 and IFC4 exports are separate schema tracks. The immutable upstream revision is `66c0737e7a48d7e0ce9303f213d88f670cb27855` in the `sylvainHellin/ifc-bench` Hugging Face dataset.

`repository-inventory.json` records every upstream file. `acquisition.json` records downloaded byte lengths, SHA256 digests and upstream LFS digests. The supported Hugging Face API/download client resolves and downloads the pinned revision. All 50 actual IFC byte streams match their upstream LFS hashes, have STEP headers and complete STEP trailers. Supporting project cards, licenses, images, PDFs and bills of quantities are retained locally. Source IFC and supporting assets are excluded from the application package.

`data-license-register.json` retains project attribution and complete license/card text. License ambiguities are recorded, including the office license text referring to the clinic and incomplete upstream attribution in several other projects. Dataset availability is not treated as permission for commercial redistribution. QA tables are inventoried but are not routing ground truth.

`campaign.json` and ignored `audits/` artifacts account for every imported physical object and every source file. All 50 files complete import; individual geometry and placement failures remain explicit blockers. The two original Sixty5 electrical/plumbing writer failures exposed nonfinite placement axes; their logs remain and the successful retry records these placements as invalid. Import completion never means coordination approval.

The complete corpus accounts for 260,604 physical objects, 294,097 declared distribution ports and 132,105 declared port relationships. Display geometry contains 74,158,854 vertices and 141,614,453 triangles. These are display approximations with no certified tessellation deviation bound. Every mesh carries its source SHA/STEP identity; duplicate GUIDs are reported rather than merged. Original unit conversion and world placements are preserved. Inferred connections are kept separate and remain empty where no inference was executed.

`digital-hub-datum.json` records the generic shared-anchor local federation proof. Digital Hub sources share project, site and building GUIDs and matching local placement/storey evidence. The measured source-to-reference translations are retained. Architecture reports site reference elevation 519 m while the other files report zero, so global geospatial registration remains unresolved. No independent model centering is used.

Native route verification uses serialized native IFC BReps with a separate OCP binding. The checker tests positive Boolean common solid volume, including complete containment, then minimum native-shape distance. Fixed numerical and kernel tolerance ambiguity prevents a pass near contact. This is numerical CAD evidence, not a formally certified interval proof. Unsupported geometry remains blocked.

Source face sewing can promote closed original face sets only when all faces are retained, no caps or hulls are added, no free/multiple/deleted edges/faces remain and the resulting original-orientation solids are valid with positive volume. Where native solid validity remains unresolved, the default policy admits only independently checked exact planar source enclosures. A scenario may explicitly select `NATIVE_CAD_WITH_SOURCE_VERTEX_HULL_ENCLOSURES`: this checks separation from a rational outer box containing every allowed affine vertex-hull completion of every declared source face. It does not establish validity of the native source solid, arbitrary CAD projections, or undocumented physical extents. A route close to an unresolved object's enclosure remains blocked. Missing geometry without a source enclosure always blocks.

The native source cache stores checker-produced BRep/support artifacts keyed by exact source bytes, loaded implementation digests, numerical policy and kernel versions. A fresh worker checks artifact digests, physical identity/completeness, native topology and exact source enclosure certificates. It does not cache candidate margins or pass flags. Corruption causes a rebuild. Cancellation and pause callbacks occur at consistent object, pair and publication boundaries.

`duplex-native-export-v4.json` is actual IFC2X3 export/reimport fidelity evidence: original STEP records unchanged, physical circular straight sections and tangent revolved elbows, valid native solids, explicit directed ports and system membership. IFC4 uses the corresponding specific pipe/duct element classes. New route geometry represents the fixed outer service envelope including specified insulation; no bore, material or hydraulic adequacy is invented. This fidelity evidence alone is not route coordination evidence. Real seeded route repair evidence lives in `../benchmarks/real-repair/` with frozen scenarios, planted interference checks, independently checked reference routes and optimizer outcomes.
